# Telegram News Bot

Новости в Telegram из RSS/Atom-лент. После подписки бот доставляет свежие материалы без дублирования уже просмотренных; раз в день отправляет дайджест из новых публикаций.

Ключевой компонент — **парсер RSS/Atom на стандартной библиотеке** (`xml.etree`), без сторонних RSS-библиотек. Такой подход исключает дополнительные зависимости и обеспечивает полный контроль над поведением парсера.

## Команды

| Команда | Назначение |
|---|---|
| `/news [URL]` | свежие новости (по умолчанию Lenta.ru; свою ленту — по URL) |
| `/sources` | встроенные ленты: Lenta, Habr, BBC World, Коммерсантъ |
| `/digest on/off` | ежедневный дайджест в 9:00 |
| `/mysubs` | на какие ленты включён дайджест |
| `/latest` | последние сохранённые новости из базы |
| `/stats` | количество обработанных новостей, число подписок |

## Особенности парсинга RSS/Atom

RSS и Atom — два различных формата; реальные ленты часто содержат отклонения от спецификации. Выявлены и обработаны следующие случаи:

1. **Namespace.** Наивный поиск `findall(".//entry")` возвращает пустой результат при объявленном namespace (`{http://www.w3.org/2005/Atom}entry`). Решение — поиск по **локальному имени** тега с игнорированием namespace. Парсер работает с лентами произвольной схемы.
2. **`dc:date` без декларации префикса.** Некоторые ленты используют `dc:date` без объявления `xmlns:dc`, что приводит к ошибке префикса в expat. Обработка реализована таким образом, чтобы некорректная лента не приводила к сбою бота.
3. **Кодировки.** Ленты поступают в UTF-8, windows-1251 и других кодировках. Парсер передаёт expat'у байты — кодировка определяется по декларации. Дополнительно применяется `html.unescape` для HTML-сущностей в заголовках.
4. **RDF-ленты** — корневой тег может быть `rdf:RDF`, а не `rss`; схема определяется по корневому тегу с учётом регистра (встречаются варианты `RSS` и `rss`).

## Дедупликация и дефект дайджеста

Новости хранятся в SQLite с `UNIQUE(link)` — одна и та же статья не доставляется дважды даже при повторном чтении ленты.

Выявленный дефект: **первая версия дайджеста отправляла уже просмотренные новости** — фильтрация выполнялась по наличию ссылки, а не по факту просмотра пользователем. Дефект обнаружен в ходе код-ревью; в текущей версии `save_articles` возвращает список **только новых** элементов, и дайджест отправляет их, а не все подряд.

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export NEWS_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export NEWS_DEMO_MODE=1               # 0 — реальные ленты, требуется интернет
python bot.py
```

На Windows — `run_bot9.cmd` (токен из корневого `.env`).

## Структура проекта

```
bot.py          — команды, дайджест, подписки
rss_parser.py   — namespace-агностичный парсер RSS 2.0 / Atom / RDF (чистый stdlib)
db.py           — aiosqlite: статьи, дедупликация UNIQUE(link), подписки
utils.py        — TTL-кэш и retry с джиттером
middlewares.py  — троттлинг и логирование
config.py       — настройки из переменных окружения
tests/          — 7 тестов (RSS, Atom с namespace, кодировка из байтов, даты, дедуп, подписки на дайджест)
```

## Планы развития

- преобразование HTML-версии статьи в читабельный текст (в настоящее время — ссылка + заголовок);
- фильтрация новостей по темам (ключевые слова);
- отправка изображения-превью из ленты.

## Тесты

`pytest tests/ -q` — 7 тестов. GitHub Actions прогоняет их при каждом push.
