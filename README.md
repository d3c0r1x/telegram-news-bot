# Telegram News Bot

Новости в Telegram из RSS/Atom-лент. Подписался — и бот сам приносит свежее, не дублируя уже прочитанное, а раз в день присылает дайджест из новых материалов.

Главное в проекте — **парсер RSS/Atom на чистой стандартной библиотеке** (`xml.etree`), без единой сторонней RSS-библиотеки. Потому что сторонние — это зависимость, а разобраться самому оказалось и полезнее, и интереснее.

## Команды

| Команда | Что делает |
|---|---|
| `/news [URL]` | свежие новости (по умолчанию Lenta.ru, свою ленту — по URL) |
| `/sources` | встроенные ленты: Lenta, Habr, BBC World, Коммерсантъ |
| `/digest on/off` | ежедневный дайджест в 9:00 |
| `/latest` | последние сохранённые новости из базы |
| `/stats` | сколько новостей уже обработано, число подписок |

## Парсинг RSS/Atom: это была боль, но полезная

RSS и Atom — два разных формата, и ленты в дикой природе бывают грязными. По пути я споткнулся о четыре вещи:

1. **Namespace.** Наивный `findall(".//entry")` находит ровно ноль, если у ленты объявлен namespace (`{http://www.w3.org/2005/Atom}entry`). Решение — искать по **локальному имени** тега, игнорируя namespace. Теперь парсер ест любые ленты.
2. **`dc:date` без декларации префикса.** Некоторые ленты используют `dc:date`, не объявив `xmlns:dc` — expat падает с ошибкой префикса. Обрабатываю аккуратно, чтобы одна кривая лента не роняла бота.
3. **Кодировки.** Ленты приходят в UTF-8, windows-1251 и чём угодно ещё. Парсер отдаёт expat'у байты — он сам читает декларацию. Плюс `html.unescape` для HTML-сущностей в заголовках.
4. **RDF-ленты** — корневой тег может быть `rdf:RDF`, а не `rss` — определяю схему по корневому тегу (с учётом регистра, это тоже было: `RSS` против `rss`).

## Дедупликация и баг с дайджестом

Новости хранятся в SQLite с `UNIQUE(link)` — одна и та же статья не придёт дважды, даже если лента перечитана заново.

Интересный баг: **первая версия дайджеста отправляла уже виденные новости** — я фильтровал по «есть ли ссылка», а не по «видел ли пользователь». Поймал это на код-ревью: теперь `save_articles` возвращает список **только новых** элементов, и дайджест шлёт их, а не всё подряд.

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export NEWS_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export NEWS_DEMO_MODE=1               # 0 — реальные ленты, нужен интернет
python bot.py
```

На Windows — `run_bot9.cmd` (токен из корневого `.env`).

## Из чего состоит

```
bot.py          — команды, дайджест, подписки
rss_parser.py   — namespace-агностичный парсер RSS 2.0 / Atom / RDF (чистый stdlib)
db.py           — aiosqlite: статьи, дедупликация UNIQUE(link), подписки
utils.py        — TTL-кэш и retry с джиттером
middlewares.py  — троттлинг и логирование
config.py       — настройки из переменных окружения
tests/          — 6 тестов (RSS, Atom с namespace, кодировка из байтов, даты, дедуп)
```
